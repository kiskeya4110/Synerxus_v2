# Synerxus - Connect. Collaborate. Impact Globally.

## Overview

Synerxus is an AI-powered platform designed to connect global volunteers with opportunities and enable organizations to track, measure, and visualize the impact of their volunteer initiatives. It links activities to humanitarian outcomes and Sustainable Development Goals (SDGs), providing data-driven insights for impact assessment and storytelling. The platform's core vision is "Intelligent connections for sustainable development worldwide."

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### UI/UX Decisions
The platform features a role-based dashboard with optimized color schemes, including UN SDG colors for charts. It is mobile-optimized with responsive layouts and utilizes `shadcn/ui` components built on `Radix UI`. The theme is light, with a very light blue-gray background and vibrant accent colors. Branding includes an infinity loop logo, navy blue and orange-gold scheme, and consistent typography. Official UN SDG graphics are integrated and displayed numerically. Interactive elements like clickable profile sections and hover states are prevalent, with clear navigation cues.

### Technical Implementations
The frontend is built with React 18, TypeScript, Vite, Wouter for routing, TanStack Query, Tailwind CSS, Chart.js, React Hook Form, and date-fns. The backend uses Node.js with TypeScript, Express.js for REST APIs, WebSockets for real-time updates, and Drizzle ORM with Neon serverless PostgreSQL. The database schema is relational and comprehensive, including AI tracking fields. An AI matching algorithm (`server/matching-algorithm.ts`), implemented in TypeScript, provides weighted scoring for volunteer-opportunity and volunteer-organization matches: Skills 35%, Location 25%, SDG 20%, Interests 20%. The algorithm includes robust data normalization (`normalizeSkills()`, `normalizeLocation()`), tiered location matching (exact city 100%, country 60%, region/partial 40%, remote 100%), and baseline scoring (20-30%) for incomplete profiles to encourage profile completion. Location matching correctly differentiates single-component ("Zambia") vs multi-component ("Lusaka, Zambia") locations to prevent false city matches. Multi-tenant security enforces strict data scoping by `organizationId` or `userId` at the database level using header-based authentication (`x-user-id`) automatically included in all API requests via `apiRequest()` and `getQueryFn()` helpers. **Data Partitioning (Strict Isolation):** Volunteers have strict per-assignee scoping and only see data they directly contributed to: (1) **Activities**: Only their own logged activities filtered by `userId`. (2) **Tasks**: Only tasks explicitly assigned to them via `assigneeId`, not all project tasks. (3) **Project Impacts**: Only impacts recorded during active assignment periods (between `respondedAt`/`assignedAt` and `completedAt` or present for active assignments), preventing inheritance of historical project data and gap-period leaks for volunteers with multiple assignments. (4) **Projects**: Only projects with accepted assignments (statuses: `active`, `completed`, `on-hold`; excluded: `pending`, `declined`). Pending assignments are NOT visible until accepted to prevent volunteers from seeing impact scores and SDG data from projects they haven't joined yet. **Application-to-Assignment Workflow**: When an application is accepted via `/api/applications/:id/review`, the system automatically creates a project assignment with `status: "active"` and `respondedAt: new Date()`, ensuring volunteers immediately see their accepted projects in the dashboard and can start tracking activities. **Opportunity List Management**: Applied opportunities are automatically filtered from the "New Opportunities" list in the dashboard and appear in the volunteer's application history, preventing duplicate applications and improving UX. The filtering logic uses both `rejectedIds` and `appliedIds` from the opportunity status API (`/api/opportunities/status`). (5) **Status Normalization**: All status comparisons use case-insensitive matching (`.toLowerCase()`) to handle database inconsistencies in project and task statuses. Organizations see all data from projects owned by their organization. The `getVisibleProjectIdsForVolunteer()` helper in `dashboard-service.ts` enforces consistent visibility rules across all volunteer-facing endpoints, ensuring volunteers never inherit data they didn't contribute to. Key features include email-based profile linking, a full messaging system, automatic project completion tracking with WebSocket updates, real-time volunteer list updates via cache invalidation, and server-side enrichment of dashboard tasks with project metadata. A centralized `opportunity-enrichment-service` provides consistent data for opportunities. The project assignment workflow includes pending invitations, acceptance/declining functionality, and duplicate assignment prevention. Impact Over Time is visualized through a multi-line Chart.js graph, and detailed SDG information is managed centrally and displayed via reusable components. A comprehensive notification system (`server/notification-service.ts`) creates real-time notifications for 8 event types (project updates, assignments, task assignment, application status changes, messages, opportunity matches, project completion, and volunteer joins), with storage methods for creating, fetching, and marking notifications as read.

### Feature Specifications
The platform includes a rebranded landing page with an interactive SDG wheel. The dashboard offers role-based views with real-time KPIs, interactive cards, Impact Over Time and SDG Distribution visualizations, and AI-matched opportunities for volunteers. A dedicated "Volunteer Insights" dashboard section provides comprehensive volunteer data, including profile completeness, application statistics, and hours breakdown per project. SDG mapping visualizes project alignment with UN SDGs. Other features include mobile data collection, a full-featured calendar, interactive impact visualization, AI-powered impact storytelling, and core management pages for Projects, Tasks, Volunteers, Organizations, Calendar, Opportunities, and Applications with full CRUD capabilities. A robust volunteer opportunities system supports posting, discovery, and application tracking with separate sections for applied and available opportunities, category-based filtering, and interactive status badges. The system supports dual user types (Volunteer/Organization) with distinct flows. Project-task hierarchy is supported with AI-powered volunteer recommendations for task assignments in both create and edit workflows. Comprehensive profile settings with photo upload are available. Multi-step intake forms are provided for onboarding volunteers and organizations, and for opportunity posting. Authentication is handled via Firebase Auth with Google OAuth, supporting intelligent redirects and session persistence. **Assignment Tracking:** Volunteers can view enriched assignment details including team members (up to 5 active volunteers on the same project) and recent activities (last 5 activities on that project) directly in the assignments page, with proper authentication ensuring volunteers only access their own data.

### System Design Choices
Authentication is managed via Firebase Auth with Google OAuth. Client-server communication utilizes RESTful APIs, WebSockets for real-time updates, and React Query. Data processing involves client-side collection, Zod validation, Drizzle ORM for PostgreSQL, server-side aggregation, and client-side visualization. The frontend is deployed with Vite, the backend with Node.js and compiled TypeScript, and the production database uses Neon.
