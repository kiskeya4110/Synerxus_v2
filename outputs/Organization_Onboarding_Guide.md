## Welcome to the Command Center

### What is Synerxus?

Synerxus is a global platform connecting your organization with skilled volunteers who want to contribute to causes they care about. Our AI-powered matching system finds volunteers whose skills, availability, and passions align with your project needs.

### The Synerxus Advantage for Organizations

| Traditional Approach | Synerxus Platform |
|---------------------|-------------------|
| Post and pray recruitment | AI-matched talent pipeline |
| Manual skill verification | Pre-verified volunteer profiles |
| Spreadsheet tracking | Real-time dashboards |
| Anecdotal impact stories | Blockchain-verified AIUs |
| Limited to local network | Access to global talent pool |

## Step 1: Organization Profile Setup

A complete profile increases volunteer applications by **4x**!

### 1.1 Basic Information

Navigate to **Settings > Organization Profile**:

[SCREENSHOT: Organization Profile Settings]

| Field | Description | Best Practice |
|-------|-------------|---------------|
| **Organization Name** | Legal or DBA name | Use your most recognizable name |
| **Description** | 500-character overview | Lead with impact, not history |
| **Logo** | Square image, 500x500px min | High-resolution, simple design |
| **Website** | Your organization's URL | Keep it updated |
| **Contact Email** | Primary volunteer contact | Use a monitored inbox |
| **Phone** | Optional direct line | For urgent coordination |

### 1.2 Organization Type

Select your classification:

| Type | Examples | Volunteer Expectations |
|------|----------|------------------------|
| **NGO** | International relief, development | Remote & field work |

## Step 3: Creating Projects (Opportunity Builder)

### 3.1 Project Title Best Practices

Your title is the first thing volunteers see. Make it compelling!

**Good Examples:**
| Title | Why It Works |
|-------|--------------|
| "Data Analyst for Education Impact Study" | Clear role + context |
| "Graphic Designer: Annual Report Campaign" | Skill + deliverable |
| "Remote Web Developer - School Portal" | Location + project |

**Bad Examples:**
| Title | Problem |
|-------|---------|
| "Volunteer Needed" | Too vague |
| "Help Us!" | No information |
| "Various Roles Available" | Not specific |

### 3.2 Description Writing Tips

[SCREENSHOT: Project Creation Form]

Structure your description:

```markdown
## About This Project
[2-3 sentences on project context and importance]

## What You'll Do
- [Specific task 1]
- [Specific task 2]
- [Specific task 3]

## What You'll Achieve
[Describe the impact of their contribution]

## What We're Looking For
[Key skills and attributes]

## Time Commitment
[Hours/week, duration, flexibility]
```

**Good Description:**
> "Join our team building a mobile learning app for students in rural Philippines. You'll design user interfaces, conduct user testing with local communities, and help us reach 2,000 students by Q2. Looking for a UX designer comfortable with low-bandwidth considerations. 10 hours/week for 3 months, flexible scheduling."

### 3.3 SDG Mapping (Auto-Suggestion)

As you write your description, Synerxus suggests relevant SDGs:

```
Detected Keywords → Suggested SDGs
─────────────────────────────────────
"education"        → SDG 4: Quality Education
"rural"            → SDG 10: Reduced Inequalities
"mobile app"       → SDG 9: Innovation
"students"         → SDG 4: Quality Education
```

> 💡 **Pro Tip:** Accept auto-suggestions, then fine-tune. Manual SDG selection ensures accurate volunteer matching.

### 3.4 Skills Configuration

#### Required vs. Preferred Skills

| Type | Definition | Matching Impact |
|------|------------|-----------------|
| **Required** | Must-have for the role | Filters out non-matches |
| **Preferred** | Nice-to-have additions | Boosts match score |
| **Critical** | Deal-breaker if missing | Flags `MISSING_CRITICAL_SKILL` |

**Example Configuration:**

```
Required Skills:
  ✅ UX Design (marked as CRITICAL)
  ✅ Mobile App Design
  ✅ User Research

Preferred Skills:
  ○ Figma
  ○ Adobe XD
  ○ Prototyping
```

#### Skill Proficiency Requirements

| Level | When to Require |
|-------|-----------------|
| **Entry-Level** | Training/learning opportunities |
| **Intermediate** | Standard project work |
| **Expert** | Leadership, complex deliverables |

### 3.5 Location Type

| Type | Description | Who Applies |
|------|-------------|-------------|
| **Remote** | Work from anywhere | Global talent pool |
| **On-Site** | Must be physically present | Local volunteers |
| **Hybrid** | Mix of both | Flexible arrangements |

### 3.6 Hours & Duration

| Setting | Options | Considerations |
|---------|---------|----------------|
| **Hours/Week** | 1-40 hours | Be realistic, not aspirational |
| **Duration** | 1 week - 12+ months | Match to deliverables |
| **Schedule** | Flexible / Fixed | Fixed = specific meeting times |

### 3.7 Minimum Verification Level

| Requirement | When to Use |
|-------------|-------------|
| **Level 1** | General opportunities, low risk |
| **Level 2** | Standard projects, client contact |
| **Level 3** | Sensitive roles, leadership, access to vulnerable populations |

> ⚠️ **Common Mistake:** Requiring Level 3 for all roles. This eliminates 80% of volunteers. Reserve for truly sensitive positions.

## Step 4: Setting Attribution Factors

### 4.1 What Attribution Weight Means

**Attribution Weight** determines what percentage of project impact is credited to volunteers in that role. This affects AIU (Attributable Impact Unit) calculations.

```
Project Impact: 1,000 students educated

Role Allocation:
├── Curriculum Developer (40% attribution) → 400 AIU
├── Tutors (35% attribution)              → 350 AIU
├── Admin Support (15% attribution)       → 150 AIU
└── Project Coordinator (10% attribution) → 100 AIU
                                          ─────────
                              Total:      1,000 AIU
```

### 4.2 Attribution Guidelines

| Attribution Range | Role Type | Examples |
|-------------------|-----------|----------|
| **10-30%** | Support Roles | Admin, logistics, data entry |
| **40-60%** | Skilled Contributors | Designers, developers, trainers |
| **70-90%** | Expert/Lead Roles | Project leads, specialists, consultants |

### 4.3 Best Practices

**Do:**
- ✅ Total attributions should equal 100% per project
- ✅ Weight based on impact contribution, not hours
- ✅ Be consistent across similar projects
- ✅ Communicate weights to volunteers

**Don't:**
- ❌ Give everyone equal attribution regardless of role
- ❌ Change weights after project starts
- ❌ Use attribution as performance punishment

> 💡 **Pro Tip:** Volunteers can see their potential AIU earnings on opportunity listings. Fair attribution attracts better talent!

## Step 5: Talent Management

### 5.1 Understanding Match Scores & Tiers

When volunteers apply, you see their AI-calculated Match Score:

```
┌─────────────────────────────────────────────────────────────┐
│                    MATCH TIERS                               │
├───────────┬─────────────┬───────────────────────────────────┤
│ EXCELLENT │  80-100%    │ 🌟 Strong fit, prioritize review  │
│ GOOD      │  60-79%     │ ✅ Solid candidate, worth meeting │
│ FAIR      │  40-59%     │ ⚡ Gaps exist, interview carefully │
│ POOR      │  0-39%      │ ⚠️ Significant mismatch           │
└───────────┴─────────────┴───────────────────────────────────┘
```

### 5.2 Reading Match Flags

[SCREENSHOT: Application Review Panel]

Watch for these flags on applications:

| Flag | Meaning | Your Action |
|------|---------|-------------|
| 🔴 `MISSING_CRITICAL_SKILL` | Lacks a required skill marked critical | Usually decline |
| 🟡 `TIMEZONE_CHALLENGE` | 6+ hour difference from your HQ | Ask about availability |
| 🟡 `EXPERIENCE_GAP` | Below your stated experience requirement | Assess transferable skills |
| 🟡 `AVAILABILITY_MISMATCH` | Can't meet full hour commitment | Discuss flexible options |
| 🟢 `TOP_MATCH` | Excellent fit across all factors | Respond quickly! |
| 🟢 `RETURNING_VOLUNTEER` | Has worked with you before | Check past performance |
| 🟢 `VERIFIED_SKILLS` | Certifications validate claimed skills | High trust |

### 5.3 Application Review Workflow

```
New Application
      ↓
┌─────────────────┐
│ Review Profile  │ ← Match Score, Skills, Availability
└────────┬────────┘
         ↓
┌─────────────────┐
│ Check Flags     │ ← Any blockers?
└────────┬────────┘
         ↓
    ┌────┴────┐
    ↓         ↓
┌───────┐ ┌───────┐
│ ACCEPT│ │DECLINE│
└───┬───┘ └───┬───┘
    ↓         ↓
  Message   (Optional)
  Volunteer  Feedback
```

### 5.4 Accept/Decline Best Practices

**When Accepting:**
- Send a welcome message within 24 hours
- Provide clear next steps
- Set expectations for first meeting

**When Declining:**
- Be prompt (within 3-5 days)
- Be kind (optional: provide reason)
- Encourage future applications if appropriate

**Template: Acceptance Message**
```
Hi [Name],

Great news! We'd love to have you join our [Project Name] team.

Next Steps:
1. Join our orientation call on [Date/Time]
2. Review the project brief (attached)
3. Set up your first 1:1 with [Manager Name]

Looking forward to working together!

[Your Name]
```

### 5.5 Volunteer Communication

| **Welcome Message** | After acceptance | In-app + email |

## Step 7: Verification (The Money Step)

### 7.1 Why Verification Matters

Verification is where volunteer work becomes **verified impact**. Unverified activities:
- Don't generate AIUs
- Don't count toward corporate funding metrics
- Don't appear on official impact reports
- Don't unlock volunteer rewards

**This step is critical!**

### 7.2 Daily Verification Queue

[SCREENSHOT: Verification Queue]

Check your verification queue daily:

```
┌─────────────────────────────────────────────────────────────┐
│              PENDING VERIFICATIONS (12)                      │
├─────────────────────────────────────────────────────────────┤
│ ⏳ Jane D. - 4 hrs - Curriculum Development - Dec 15       │
│ ⏳ Mike R. - 2 hrs - User Testing Session - Dec 14         │
│ ⏳ Sarah L. - 6 hrs - Workshop Facilitation - Dec 14       │
│ ⏳ Ahmed K. - 3 hrs - Data Analysis - Dec 13               │
│    ... 8 more                                               │
│                                                             │
│ ⚠️ Oldest pending: 5 days (Ahmed K.)                        │
│ 📊 Avg. verification time: 2.3 days                         │
└─────────────────────────────────────────────────────────────┘
```

### 7.3 Evidence Review Process

For each submitted activity:

| Evidence Type | What to Check | Verification Method |
|---------------|---------------|---------------------|
| **Photo** | Matches description, dated | Visual inspection |
| **Document** | Deliverable complete, quality acceptable | Content review |
| **GPS Geofence** | Location matches project site | System-verified |
| **Video** | Activity occurred as described | Sample viewing |
| **QR Scan** | Volunteer was present at event | System-verified |

### 7.4 Verification Decision Flow

```
Review Submission
       ↓
┌──────────────────┐
│ Evidence Present?│
└────────┬─────────┘
    Yes  │  No
    ↓    └──→ Request More Info
    ↓
┌──────────────────┐
│ Activity Matches │
│ Description?     │
└────────┬─────────┘
    Yes  │  No
    ↓    └──→ Reject with Feedback
    ↓
┌──────────────────┐
│ Hours Reasonable?│
└────────┬─────────┘
    Yes  │  No
    ↓    └──→ Adjust Hours or Discuss
    ↓
   ✅ APPROVE
       ↓
   AIUs Minted!
```

### 7.5 What Happens When You Verify

When you approve an activity:

1. **AIU Minting** - Impact units calculated and assigned
2. **Blockchain Record** - Immutable verification proof created
3. **Volunteer Credit** - Hours and impact added to profile
4. **Syner-G Points** - Volunteer earns gamification rewards
5. **Report Update** - Impact appears in your dashboards
6. **Corporate Trigger** - May release funding from CSR partners

### 7.6 Verification Methods

| Method | How It Works | Best For |
|--------|--------------|----------|
| **Manual Review** | You inspect evidence and approve | Remote work, documents |
| **GPS Geofence** | System verifies location was correct | On-site activities |
| **Photo AI** | AI validates photo authenticity | Event attendance |
| **QR Scan** | Volunteer scans code at event | Workshops, gatherings |
| **Peer Confirmation** | Another volunteer confirms | Team activities |

> ⚠️ **Common Mistake:** Letting verifications pile up. Delayed verification frustrates volunteers and delays funding!

7. Download or share directly
